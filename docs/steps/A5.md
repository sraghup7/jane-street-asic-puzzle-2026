## 1. One deliberate deviation from the plan

The plan said to append this section to `pinmodel.json`. It is a **separate file** instead, because
A4's gate asserts that re-running `pin-geom` reproduces `pinmodel.json` **byte for byte** — an
appended key would break that guarantee for a stage that does not own the file. Each stage owns its
own artifact; a coverage report reading three artifacts is its own stage.

## 4. The finding Phase B is built on

Where do cell pins actually meet the interconnect? The answer is narrower than expected:

| routing layer | pins with geometry on it |
|---|---|
| `67/20` (li1) | **489** — every routed pin |
| `68/20` (met1) | 20 |
| `69/20` … `72/20` (met2–met5) | **0** |

And the 20 met1 pins split into two groups: **17 supply pins** in 7 masters (`and3_2`, `and3b_2`,
`clkbuf_16`, `dfstp_2`, `dfxtp_2`, `tapvpwrvgnd_1`), plus exactly **3 signal pins** —
`dfrtp_2:RESET_B`, `dfstp_2:SET_B`, `xor2_2:B`.

**The consequence, which changes how Phase B must extract nets.** A1 established that li1 carries no
top-level routing at all (role `local_wire`; top-cell shape count 0), while the router's interconnect
is met1–met5. So a cell pin and the wire it belongs to are **not on the same layer** — they are joined
by a *via instance*:

```
cell pin (li1 67/20)  ->  VIA_L1M1_PR_MR instance (67/44 cut)  ->  met1 routing (68/20)  ->  ...
```

There are **2696** such via instances. So B3/B4 must treat the via instances as **part of the net**,
not merely as decoration between separate conductor layers. An extractor that looked for a
pin-to-wire overlap on one layer would find almost nothing; this is precisely why the rule set from A2
has to be applied globally rather than per-layer.

input.

## 8. Carried forward to Phase B

1. **The vias are part of the net** (§4). B2/B3 must apply the A2 rule set globally: li1 pin geometry
   reaches met1 routing only through a via instance.
2. **A2's 5 rules are the whole connectivity model**; A4 already consumes them per master, B3 will
   consume them globally.
3. **A5's two known gap classes** (`VPB` ties, diode supplies) are expected and must not be reported
   as errors by later integrity checks — they are pins with no routeable geometry.
4. **No pin in any master has geometry on met2–met5.** Those layers exist only as top-level
   routing, so a net that runs on met2 or above must reach its pin through met1 and the via chain
   down to li1 — again, via instances rather than direct overlap.

## 9. Amendment, 2026-09-15: one gap class, not two

An external review (R2) found that A4's shape reader missed 135 GDSII **paths** the masters draw
(128 met1 supply rails, 7 li1 segments) because it read `cell.polygons` only. The antenna diode's
`VGND`/`VNB`/`VPWR` are each drawn as a rail path, so they looked unrouted — "antenna diode: supply
exists only as a `68/16` pin square" (§3's second gap cause, above) was that artifact, not a layout
fact. See `docs/steps/A4.md` §9 for the geometry-reading fix.

With paths included, this step's numbers change: with-routing-geometry **489 → 492** (of 560, now
**87.86 %**); without routing geometry **71 → 68**, now attributed to the **one** remaining cause
(`VPB` well-tie contacts) rather than two; §4's routing-layer reach becomes `{67/20: 492, 68/20:
209}` (met1 gains the 30 diode rail shapes it was missing); instance-level reach becomes **6955 of
7897 placed pins (88.07 %)**. §8's Phase-A summary row and Carried-forward item 3 ("A5's two known
gap classes") describe the old, two-class state; there is now one. The gate (29/29) asserts the
corrected numbers.
