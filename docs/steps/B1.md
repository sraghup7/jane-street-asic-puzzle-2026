# Step B1 — The instance table

**Stage:** `python -m tools.puzzle instances` · **Gate:** `tools/checks/check_stepB1.py` → **35/35 PASS**
**Artifact:** `recon/derived/instances.json` · **Inputs:** `puzzle.gds`, A1 `layers.json`, `inventory.json`
**Differentiator:** D1 (the placement grid and the cell boundary both come from the chip's own geometry)

Phase A described *what the cells are*. B1 fixes *where they are*, which everything after needs: B3/B4
transform the A4 pin model by these transforms, C3 clusters by these positions, C4 indexes regions
by them.

---

## 1. The convention is measured, not assumed

A GDS placement is an affine map

```
global = R * local + origin,        R = diag(sx, sy),   sx, sy in {+1, -1}
```

so for 180-degree-only placement there are exactly **four** candidate matrices per kind — `identity`,
`flip_x`, `flip_y`, `rot180`. Rather than trust a documented convention, the stage applies all four
to every instance and keeps the matrix that reproduces **every** instance's global bbox:

| kind | n | identity | flip_x | flip_y | rot180 |
|---|---|---|---|---|---|
| `rot000` | 624 | **624** | 0 | 0 | 0 |
| `rot000_mirror` | 546 | 0 | 0 | **546** | 0 |
| `rot180` | 233 | 0 | 0 | 0 | **233** |
| `rot180_mirror` | 215 | 0 | **215** | 0 | 0 |

`1618 of 1618` instances reproduced, one unanimous winner per kind:

```
rot000           R = diag(+1, +1)      rot000_mirror    R = diag(+1, -1)
rot180           R = diag(-1, -1)      rot180_mirror    R = diag(-1, +1)
```

The gate does not take this on trust: it re-runs the vote against the raw GDS and requires that the
chosen matrix be the **only** one that fits each kind. A convention that is merely one of several
fits is not a convention.

## 2. An independent witness: the warm-up DEF

`warmup/03_post_place_and_route.def` states 230 placements without reference to the GDS — explicit
coordinates in the same database units, and a named orientation. Nothing about the main chip has such
a witness, so the warm-up is the only place the convention can be checked against a second source
rather than against gdstk's arithmetic agreeing with itself.

The DEF and the GDS do **not** use the same reference point, and finding that out was the substance
of this step. A DEF placement point is the cell's lower-left corner; a GDS placement point is a corner
that *depends on the kind* (§3). Matching on the raw coordinate therefore agreed on only **96 of 230**.
Matching on the **footprint's lower-left corner** — the same physical corner under either convention —
gives:

```
DEF components parsed                                   : 230
warm-up placements indexed by cell + lower-left corner   : 230
matched to a GDS placement, cell + exact corner          : 230
unmatched                                               : 0
orientation token -> GDS kind                            : FN->rot180_mirror, FS->rot000_mirror,
                                                            N->rot000, S->rot180
```

All 230 match, and the token → kind map is a **bijection**. An independent file now corroborates the
whole convention, including which DEF token corresponds to which transform.

## 3. The placement point is an anchor, not a lower-left corner

This is the finding that would otherwise bite later. The GDS origin is a corner whose identity depends
on the kind: a kind with `sx = -1` puts it at the cell's **right** edge, a kind with `sy = -1` at its
**top** edge. So the same coordinate can name two different cells:

```
distinct placement anchors : 1327   (of 1618 placements)
anchors carrying 2+ cells  : 275
distinct global bboxes     : 1618 of 1618   <- the bbox is the unique key
```

Every one of the 275 shared anchors is a pair occupying *adjacent* space — one extending left or down
from the anchor, the other right or up. Their bounding boxes overlap only in the 0.19 µm implant
overhang, which is meant to abut. The artifact records `bbox_dbu` as the position key for this reason,
and carries the anchor semantics as data rather than leaving it in a comment.

## 4. The placements must not overlap

The cell boundary is observable, which is what makes a non-overlap check possible: A1 identified
`236/0` as a per-master footprint marker (68 of 69 masters, inset 0.19 µm in x and 0.24 µm in y from
the master bbox — unanimous across all 68). B1 now computes each instance's **global footprint
rectangle**, and the gate asserts the 1618 of them are pairwise disjoint.

That check also explains the shared anchors structurally. Every footprint is exactly **2720 DBU**
(2.72 µm) tall while the row lines are **5440 DBU** apart:

| | |
|---|---|
| footprint height | 2720 DBU, identical for all 1618 |
| row line pitch | 5440 DBU = **two** cell rows |

A cell anchored at a row line with `sy = +1` occupies the band above it; with `sy = -1`, the band
below. So one 5440 band carries two stacked cells **sharing one anchor y** — which is exactly the
co-anchored pairs of §3, and why they are legal placement rather than a collision. `tapvpwrvgnd_1`
carries no footprint marker, so its footprint is its bbox inset by the inset the other 68 agree on; the
fallback is recorded in the artifact and asserted by the gate.

## 5. What the gate asserts

35 checks in seven groups:

0. **Regenerability** — the stage is re-run hermetically and must reproduce the artifact byte for byte.
1. **Totals** — 1618 placements against Step 1's census; 69 masters; 52 rows; the kind histogram equal
   to `inventory.json`'s `std_cell_transforms`; per-master counts equal Step 1's census exactly; ids
   unique and dense.
2. **The convention, re-measured in the gate against the raw file** — master bboxes and footprints
   rebuilt from the GDS must equal the artifact's; `transform(master_bbox) == instance_global_bbox` for
   all 1618; and the chosen matrix unique per kind.
3. **Table geometry** — every bbox contains its own footprint; all 1618 bboxes distinct; every anchor
   on the site and row pitches; row lines contiguous and complete; footprint height and width uniform
   and site-aligned.
4. **Non-overlap** — no two footprints intersect.
5. **The DEF oracle, re-derived** — 230 components indexed without collision, all matched, the token
   map a bijection, and the artifact's recorded result agreeing.
6. **Marker provenance** — 68 of 69 masters carry the marker, the inset unanimous, the one fallback
   documented.

## 6. A trap this step confirmed

The first attempt at §2 failed and produced a wrong answer (96/230) because it compared a footprint in
**microns** against an anchor in **DBU**. Same class of bug the audit found in the recompute gate:
gdstk hands back microns, everything downstream is integer DBU. `instances.py` converts exactly once,
in a single `dbu()` function called at read time, and every stored coordinate is an integer. Two
occurrences in two steps is enough to treat "convert once at read time" as a rule with teeth rather
than a convention on paper.

## 7. Carried forward

1. **B4 must use `bbox_dbu` / `footprint_dbu`, not the anchor, as the geometric position.** The anchor
   is not a unique cell position (§3); the footprint is, and it is the region a pin's geometry can
   legitimately lie in.
2. **The pin model transfers to the warm-up unchanged** — the audit's recompute gate established the
   warm-up's cell and via masters are geometrically identical to the puzzle's, so B7 is a fair
   regression rather than a second extraction problem.
3. **`footprint_dbu` gives B5's "floating input" and C3's spatial clustering a physical cell region**
   without re-deriving the `236/0` marker.
4. **The DEF is spent as an oracle.** It covers the warm-up only; the main chip has no independent
   placement witness, so B1's main-chip verification rests on the 1618/1618 bbox reproduction and the
   uniqueness of the matrix per kind.
