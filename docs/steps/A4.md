# Step A4 — Master-local pin geometry

**Stage:** `python -m tools.puzzle pin-geom` · **Gate:** `tools/checks/check_stepA4.py` → **40/40 PASS**
**Artifact:** `recon/derived/pinmodel.json` · **Inputs:** A1 `layers.json`, A2 `via_pairs.json`, A3 `pin_names.json`
**Differentiator:** D2 (no PDK LEF) · **Calibrated against:** `warmup/04_final.gds` vs `warmup/02_netlist_with_power_rails.v`

A3 gave each master its pin *names*. A4 gives each pin the **geometry it occupies**, in master-local
coordinates — the rects B4 will match against the router's nets.

---

## 1. Method

**The connectivity rule.** A4 reuses A2's proved rule set rather than inventing one. Within a master,
two shapes are connected if they are on the same physical layer and touch, or if a cut layer bridges
them:

```
67/44 :  67 <-> 68        68/44 : 68 <-> 69        69/44 : 69 <-> 70
70/44 :  70 <-> 71        71/44 : 71 <-> 72
```

**The subtlety that decides the whole step.** A cut layer's *layer number* is shared with the layer it
sits on — `67/44` is the li1→met1 cut and its layer number is 67, the same number as li1 — so a cut
cannot be treated as a plane shape just because the number matches. Roles separate them: a node is a
**cut** iff its pair is `via_cut` or `contact`, and plane shapes are grouped into one physical layer by
*layer number*. That correctly merges `67/16` with `67/20` (both li1) and never with `67/44`.

**The algorithm.** Build a graph over one master's electrical shapes (`routing`, `local_wire`, `pin`,
`via_cut`, `contact`); seed it from the pin's label; take the connected component.

**Scope, stated explicitly.** Only the routing stack is traced. Device layers (well, diffusion, poly)
are deliberately not traversed: descending into the diffusion network would merge distinct pins
through the cell's transistors, and nothing downstream needs it — we reconstruct *connectivity* at the
cell granularity, not transistors.

**Exactness.** Two tests had to be exact rather than approximate, and both were wrong at first:

- **Touch**: `gdstk.offset` grows one operand by 5 nm, then an exact boolean intersection decides.
  Growing is what makes *abutting* shapes count as connected — a wire drawn as abutting rectangles is
  one wire, and merging only *overlapping* polygons is the published work's trap T5.
- **Containment**: `gdstk.inside` for true point-in-polygon seeding.

## 2. The warm-up calibration — and the bug it caught

The same code path (`layers.classify_all` → `derive_pin_label_layers` → cell graph) is run on
`warmup/04_final.gds`, and the pin names it produces are compared against the port names the vendor
netlist connects by name:

```
18 cell types, all match: True
```

| cell type | our layout reading == the netlist's port names |
|---|---|
| `nand2_2` | `A B VGND VNB VPB VPWR Y` |
| `dfrtp_2` | `CLK D Q RESET_B VGND VNB VPB VPWR` |
| `mux2_1` | `A0 A1 S VGND VNB VPB VPWR X` |
| `decap_3` | `VGND VNB VPB VPWR` |
| `tapvpwrvgnd_1` | `VGND VPWR` |

Two artifacts with no shared input, agreeing exactly, over all 18 types. If the warm-up used a
different code path this would prove nothing, which is why `classify_all` was factored out of A1's
stage specifically so this could reuse it.

### Bug 1 — a bounding-box touch test merged every pin in the cell

The first version tested touching with bounding boxes. Since li1 inside a standard cell is not
rectilinear, that over-connects: **every signal pin of a master came back with the same 17-shape
component.** `A` and `B` shared their geometry, and `A`, `B`, `Y`, `VGND`, `VPWR` were all identical.

The tell was arithmetic, not an error message: identical `n_shapes` and identical area for pins that
cannot be the same net. Fixed by the exact inflate-and-intersect test above; total pin shapes dropped
from 2620 to 1790 as the phantom merges vanished.

This is exactly what the plan's "calibrate on the warm-up" clause is for, and it is the failure mode
the published work hit from the other direction (their trap T5).

### Bug 2 — a bounding-box seed anchored `A` and `B` to the output net

After fixing the touch test, `A` and `B` *still* shared a node. The diagnostic showed why: shape `#3`
on `67/20` is a **14-point polygon** from the output net whose bounding box is
`(0.515, 0.655)–(2.215, 2.465)`, spanning the middle of the cell. Both input labels fall inside that
*bounding box* but outside the actual outline, so bbox-based seeding anchored both of them to Y's li1.

| shape | points | layer | what it is |
|---|---|---|---|
| `#3` | 14 | `67/20` | Y's li1 — bbox covers both input pins |
| `#4` | 4 | `67/20` | B's li1 strap, touches B's pin squares only |
| `#5` | 4 | `67/20` | A's li1 strap, touches A's pin squares only |

Fixed with `gdstk.inside`. `A` and `B` are now 3-shape components with distinct geometry, and Y is 4.

## 3. The anti-merge invariant

Bug 1 produced a signal that is worth asserting permanently: **if the trace over-merges, distinct pins
of one master end up with identical geometry.** So the gate checks that directly.

```
masters with two pins sharing identical routing geometry: 68
  ... ['VGND', 'VNB'] in 67 masters
  ... ['VGND', 'VNB', 'VPB', 'VPWR'] in the antenna diode
```

Every coincident group is a supply/body-tie pair, and the reason is benign and visible in the layout:
those labels are drawn at the *same coordinates*. `VGND` and `VNB` both sit at `(0.23, 0.0)`; `VPWR`
and `VPB` both sit at `(0.23, 2.72)`. The gate asserts that no *signal* pin ever joins such a group —
which is precisely the check that would have failed on the buggy version.

---

## 4. Findings

**68 `VPB` pins have no routing-layer geometry at all.** Their only shape is a single `64/16`
well-tie contact. The n-well tie is not part of the routing stack, so no net can attach to `VPB` from
outside the cell — consistent with A2 finding that no via master bridges layer 64.

**`VNB` resolves to the supply pin at the same coordinates.** Its label sits on `64/59`, and there is
no drawn geometry on layer 64/122 underneath it; the p-well tie contact lives on `122/16`, which is
not a routing-plane layer. The label therefore anchors the `68/16` pin square drawn at the same point
— i.e. `VNB` and `VGND` share geometry. The vendor netlist confirms this reading: it connects
`.VNB(VGND)`. Recorded as `seed_method: other_layer` for all 68 cases, so the fallback is never
silent.

**The antenna diode is genuinely special.** `sky130_fd_sc_hd__diode_2` is the one master whose
supplies (`VGND`, `VNB`, `VPWR`) exist only as single `68/16` pin squares with no `68/20` met1 drawing
at all — so all four of its supply/body pins coincide. It is also the only master where all four
coincide, and its signal pin `DIODE` is the largest single pin in the design (12 pin squares). It is
instantiated 10 times.
