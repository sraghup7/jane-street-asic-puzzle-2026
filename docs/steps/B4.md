# Step B4 — Every pin of every instance onto a net

**Stage:** `python -m tools.puzzle pins-to-nets` · **Gate:** `tools/checks/check_stepB4.py` → **58/58 PASS**
**Artifact:** `recon/derived/pin_net.json` · **Inputs:** `puzzle.gds`, A2, A4, B1
**Differentiator:** Δ3 (KLayout's engine, configured from our own derived data)

B3 proved the extraction is complete — every conductor shape on the die is in exactly one net.
B4 is the step that turns that into a **netlist**, by attaching terminals to those nets.

This step also uncovered the most consequential bug in the project so far, in B3's own output.
Both halves are recorded here, because B4's results only mean anything after the fix.

`unassigned_functional = 0` is B4's acceptance criterion on the nose: **every functional pin of

## 2. The bug: `cluster_id` is not a global net key

The first run of B4 reported net 2 (the `VPWR` net) carrying **15 functional pins**, all of them
`clkbuf_4.X`. That is a power net driving nothing and a signal pin sitting on power — a short.

The chase, and what each step ruled out:

* **The master is clean.** Extracting `clkbuf_4` in isolation puts X and VPWR on *different*
  nets. Direct GDS check: all five li1 polygons in the master are pairwise disjoint and do not
  touch within 1 DBU. So the merge was created by placed geometry, not by the cell.
* **Not a tie-off.** All 16 clock nets (92 flip-flop `CLK` pins) are driven by `clkbuf_8`; the
  15 `clkbuf_4` outputs drive nothing. But 8 `and3_2` outputs are *also* unused and are
  **floating** (single-terminal nets). A deliberate tie-off policy would be uniform, and this
  is not.
* **Cut layers are pristine.** Every cut layer is one uniform via size (170×170, 150×150,
  200×200, 200×200, 800×800) with no stray large shapes, so no bogus cut is bridging anything.
* **Rule bisection.** li1→met1 alone leaves X and VPWR separate; the merge is observable only
  once the met3↔met4 rule is added — so it looked like a path through the upper metals.
* **Window bisection failed** for an instructive reason: `LayoutToNetlist` refuses a clipped
  iterator outright (*"cannot work on clipped layouts"*). Rebuilding each window as a complete
  *flattened* layout, a ±100 µm window still did **not** reproduce the merge, and X's net in
  that window contained only its own pin.

That last result is the contradiction that cracked it. X's geometry is entirely local, so no
removal of distant geometry can change what X is connected to. The net key had to be at fault.

**It was.** In the hierarchical netlist, `probe_net(point)` returns the net **of the cell that
owns the shape**, and `cluster_id` is only unique **within one circuit**:

```
X     point -> cluster_id=2  circuit='sky130_fd_sc_hd__clkbuf_4'   0 subcircuit pins
VPWR  point -> cluster_id=2  circuit='puzzle'                     2590 subcircuit pins
all (circuit, cluster_id==2) pairs: 70
```

**Seventy different nets, in seventy different circuits, all carried `cluster_id == 2`.** B4's
map — and B3's supply identification before it — keyed nets on that number, so unrelated nets
were merged. The "short" never existed.

**The fix is to flatten the layout before extracting.** One circuit ⇒ `cluster_id` is a real net
identity. Re-extracting the flattened design:

```
2626 nets, 2626 distinct cluster ids
X -> 683     VPWR -> 27     same net? False
```

which also independently confirms the ±100 µm window measurement (X=683, VPWR=27). Both B3 and
B4 now run through the flattened engine, and the 15 `clkbuf_4` pins are simply *unused*, exactly
like the `and3_2` outputs — which is the answer the tie-off asymmetry predicted all along.

This is the **fourth** instance of this project's signature bug class — keying on something that
is not unique — after `check_step3`'s vacuous uniqueness test, the A-phase gates masked by
running in order, and B2's comparison over a shrinking sample. It is the most consequential,
because it produced a wrong answer that looked like a plausible finding rather than an error.

## 3. What the fix cost B3

B3 changed shape, and its *supply* claim had to be re-established rather than assumed:

| | before | after |
|---|---|---|
| nets | 729 (top circuit only) | **2626** (all, unique) |
| subcircuits | 9839 = 1618 cells + 8221 vias | gone — flattening removes them |
| net ranking | `subcircuit_pin_count()` | polygon count (0 under flattening) |
| supply identification | keyed on possibly-colliding ids | **same answer, now trustworthy** |

B3's supply identification **survives**: the two largest nets by polygon count are still
supply-only by pin name, with the same pin counts (1608 `VPWR`; 1608 `VGND` + 932 `VNB`), and
they are now an order of magnitude bigger than the next net (6974/7015 vs 824 polygons) so
"biggest" is not a knife-edge call. The numbers that were previously reported for B3 were
correct; the reasoning that produced them was not sound. The gate now asserts uniqueness
explicitly, so a regression fails loudly instead of silently merging nets.

The cost of the fix is one lost piece of evidence: the hierarchical extraction showed
**9839 subcircuits = 1618 cells + 8221 via placements**, which was independent confirmation that
the hierarchy is exactly one level deep. That measurement stands on the record in B3's own
output; the flattened path cannot reproduce it, so it is no longer asserted by any gate.

## 4. Why the terminals are probed the way they are

Three decisions, each chosen against a cheaper alternative that does not work:

* **Ask the engine, don't match geometry.** A5 established that no pin in any master has
  geometry on met2–met5, that li1 holds 489 of the 560 modelled pins and met1 only 20, and that
  li1 carries no top-level routing. A cell pin and the wire it joins are therefore never on the
  same layer — they are joined by a via instance, and the via is part of the net (§6.5). Any
  "pin rect overlaps wire polygon" test finds almost nothing.
* **Probe label positions, on the pin's own layers.** A bounding-rect centre is not inside a
  comb pin (B2 lost 32 pins to that), so points come from A4's `positions_um`, which were seeded
  from the labels. A position that lands inside one of the pin's own shapes is probed **only on
  that shape's pair**, so it cannot land inside a different net's wire on another layer.
  `position_layer_fallbacks` counts the positions where that containment test found nothing: 981
  of them — and every one is degenerate. `VPB`'s only shape sits on pair `64/16`, which is not a
  conductor pair in our stack, so that pin has no probeable pair at all: `own` is empty, the loop
  probes **nothing**, and the pin is reported with cause `no_routing_geometry`. The 30 diode
  supplies are the same case on `diode_2`. So the fallback never returns a net for an assigned
  pin — measured event by event: 951 of the 981 are `VPB`, 30 are diode supplies, all 981 on pins
  that end up unassigned. The counter is reported rather than hidden, and it is the one loose end
  this step leaves (see §6).
* **A pin's positions must agree.** Every label position of one pin is on one electrical node,
  so positions disagreeing would mean A4 or the extraction had merged two nets. Measured: **0
  conflicts** across all 7897 pins. A winner is still chosen deterministically so the stage
  always produces an artifact, but a conflict would fail the stage rather than be averaged away.

## 5. What the gate asserts

58 checks. Beyond hermetic regeneration (byte-identical, tree untouched, no stored timing):
structural coverage **in both directions** (every B1 instance present with exactly A4's pin set —
no missing pin and no invented pin); the functional/supply split and every count re-derived from
B1 + A4 rather than read from the artifact; `unassigned_functional == 0`; the gap classes
re-derived as 942 and 30 with 0 unexplained; **agreement between the artifact's two
representations** of the map (per instance and aggregated per net — terminal counts, pin names,
and the functional/supply split must all reconcile); agreement with B3 on which clusters are the
supply nets; and **an independent re-probe**: the engine is rebuilt and, for a deterministic
sample of ≥30 terminals, the recorded evidence point is probed again and must return the
recorded net. Without that last check the artifact's own probe would be the only witness to its
own evidence.

## 6. Carried forward

1. **The 981 fallbacks are wholly accounted for, and the first reading of them was wrong.** This
   note originally said 981 = 972 unassigned pins + 9 label positions sitting outside the shapes
   A4 traced, and that those 9 "still resolved to a net". Both halves are wrong. Re-derived
   event by event, the 981 are 951 `VPB` + 30 `diode_2` supplies, and **all** are on pins B4
   records as unassigned — because the path is degenerate rather than a genuine fallback: `VPB`'s
   only shape is on pair `64/16`, off the conductor set, so its pair list is empty and nothing is
   probed. The 951-vs-942 difference is not a separate class of pin: it is second label positions
   on `clkbuf_16`, `dfstp_2` and `dfxtp_2` (9 extra events). No downstream consequence, since no
   assignment rests on it — but the counter is asserted by no gate, and the artifact's own
   `method.position_layers` states the containment guarantee unconditionally, which the data
   contradicts. Both are open; see `docs/verification.md` §10 (F3).
2. **30 single-terminal nets** exist (up from 15 before the fix): the unused `and3_2` outputs,
   the `conb_1` constants' `HI`/`LO`, and the clock root's un-driven `A`. They are real
   connectivity, not failures — B5 must expect them rather than call them floating inputs.
3. **B5 inherits a trustworthy terminal set for the first time.** Single-driver and floating
   checks can now be stated against nets whose identity is unique; before this fix they would
   have been computed over merged nets.
4. **B7 must run through the flattened engine too**, and its comparison against
   `warmup/01_netlist.v` is the check that will show whether flattening changed anything about
   the warm-up partition. B2's pass was obtained on the hierarchical path.
5. **`cluster_id` is not a global key** unless the layout is flattened. Recorded in
   `docs/verification.md`; it is the kind of trap that would otherwise be re-introduced by the
   next stage that needs to name a net.
