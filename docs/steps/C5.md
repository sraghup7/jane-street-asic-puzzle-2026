# Step C5 — corroboration by the design's own answer

**Status: PARTIAL, and one part of it is a positive result.** The **existence** of a hidden constraint
beyond the four mechanical ones is now established independently of any region map. The **map itself**
is still not read, so this step cannot yet corroborate one.

Plan reference: `docs/03_our_plan.md` §C5. C5 was specified as corroboration of C4's map by a second
route. C4's map does not exist yet, so what follows is the part of C5 that can be done without it —
and it turned out to be worth doing first, because it tests the premise C4 has been assuming.

## 1. The premise test: does a hidden constraint exist at all? ✅

Every attempt to find a region decode in the logic has failed: no per-cell region decode, no diagonal,
no per-column segmentation, and the 22-point enable test finds no signal high at exactly a region's
stars. That is a lot of failure for a constraint the plan says is there, so the premise was tested
directly, with no hypothesis about the map.

**Construction.** Star patterns that satisfy *every* constraint we do understand — 22 ones, two per
row, two per column, no 8-neighbour adjacency — are generated by walking away from the winning
pattern with random **two-switches** (exchanging two rows' columns, which preserves the row and
column counts by construction), keeping only moves that leave the pattern adjacency-free.

**Result** (`probe_c5b.py`, 40 samples, all distinct from the winning pattern):

```
accepted (success)                    : 0
rejected (TRY AGAIN)                  : 40
patterns distinct from the winning one: 40 of 40
no valid pattern generated            : 0
```

**All 40 are rejected.** So the design enforces a constraint beyond 22 ones / 2 per row / 2 per column
/ no adjacency, and that is now established **without knowing anything about the map**. The plan's
premise for C4 is confirmed: there *is* a hidden constraint, and C4's difficulty is in *finding* it,
not in its existence.

> The first run of this probe printed a confident verdict from **zero samples**: the generator
> (two random permutations) never produced an adjacency-free pattern, because 22 stars on 121 cells
> is dense enough to average ~30 adjacent pairs, so the "no region constraint" branch was reached
> vacuously. The probe now tests `accepted + rejected == 0` first and reports VACUOUS instead, and the
> sampler walks from the known-good pattern. Worth recording: a confident wrong answer from an empty
> sample is exactly the failure the project's anti-vacuity rule exists to catch, and it slipped past
> until the counts were printed.

## 2. How tight is it? The winning pattern is nearly rigid under exchanges

`probe_c5c.py` tests every *single* two-switch from the winning pattern — the tightest neighbourhood
there is:

```
single two-switches tested  : 2
  accepted                  : 0
  rejected                  : 2
  skipped (created adjacency): 45 of 47
```

**45 of the 47 single exchanges cannot even be tried**, because they put a star adjacent to another.
Only two survive that filter and both are rejected.

Read carefully, that is two statements, and the weaker one is the one about rejection:

* **The neighbourhood is almost entirely blocked by adjacency** — that part rests on 45 of 47 and is
  solid. It is also *why* an answer to this puzzle is hard to find by search: the mechanical
  constraints alone leave very little room.
* **No surviving exchange is accepted** — that rests on **2** samples, so on its own it is weak. The
  real evidence that the hidden constraint bites is §1's 40 rejected patterns, not these two.

## 3. A flaw in the first oracle design, recorded so it is not repeated

`probe_c5a.py` tried to test "are these two stars in the same region?" by exchanging their *columns*,
on the reasoning that a same-region pair would keep both regions at two stars. **That reasoning is
wrong.** The exchange moves a star from cell `a` to cell `b`, so it is no-region-change only if
`region(a) = region(b)` — it tests whether the *destination cell* shares a region with the *source
cell*, not whether the two stars share one. Its 16 usable results (all `TRY AGAIN`) are therefore not
evidence about the grouping, and are not used as any.

The construction that does answer "are these two cells in one region" is a *move* plus a compensating
move, which is a harder thing to build; probing for the map is C5's job only as corroboration, and
the plan requires C4 to derive it from the logic first.

## 4. What this means for C4 and the remaining work

* The hidden constraint is confirmed to exist, so C4's target is real.
* The winning pattern is rigid: 40 distinct valid-looking neighbours all rejected, and 45 of 47 single
  exchanges blocked by adjacency before the hidden constraint is even consulted.
* The map still has to be read from the logic. The tests here are the published solution's probing
  method and can only ever corroborate a map that C4 reads first — which is exactly the distinction
  Δ5 claims.
* One more thing §1 establishes that is worth having: any candidate region map must accept the
  winning pattern and reject all 40 sampled patterns. That is a **ready-made falsification set of 41
  vectors** for a future C4 to test against, produced without knowing the map.
