# Step E1 (pulled forward) — driving the design with the winning vector

**Status: MAJOR MILESTONE — the recovered netlist reproduces the published target on the winning
input. Not complete: 4 of the 5 message classes are verified; the fifth needs the region map.**

Done early, on the user's instruction, because C3 and C4 were both blocked on the same thing: the
reference waveform contains only *failing* attempts, so the success path and 21 flops had no
behaviour to observe. Driving the winning vector gives them behaviour. It is also the cheapest
possible check of the whole recovery: `build/puzzle.v` plus our 69 cell models either reproduces the
published answer or it does not.

## The milestone

`tools/target.py` holds the target (`FEED_ORDER`: 121 bits, first bit = grid cell (0,0), row-major;
`SUCCESS_CYCLE = 126`; the message table). Probe `probe_e1a.py` copies the **reference's own rst_n
and enable timeline** and replaces only the data line, so the payload is the single variable.

The feed offset was **measured, not assumed** (offset = the cycle whose first bit lands on the
design's input): the acceptance test decides it.

```
offset   success      message stream        ones fed
  4      125          '(* TWO STARS *)'     22      <-- the winner
  5      None         'TRY AGAIN'           22
  6      None         'TRY AGAIN'           22
  7      None         'TRY AGAIN'           22
  8      None         'TRY AGAIN'           22
```

**Our netlist outputs `(* TWO STARS *)` and asserts `success` at sampled cycle 125**, i.e. the
**126th** cycle — exactly `SUCCESS_CYCLE = 126` under 1-based counting, and the only offset that
does it. Every other offset shifts the grid and correctly fails. So:

* **AC2 (success at cycle 126): met**, with the counting convention now pinned down as 1-based.
* **AC4 (`(* TWO STARS *)`): met.**
* The recovery path (GDS → connectivity → netlist → our own cell models) is validated end to end by
  the strongest available oracle: the design answers the puzzle correctly.

## The four wrong-input messages

`probe_e1c.py` builds the wrong vectors explicitly and checks the message each one produces:

```
case                           ones  expected          got               verdict
all_zeros                         0  'EMPTY SKY'       'EMPTY SKY'       OK
all_ones                        121  'BIG BANG'        'BIG BANG'        OK
two_per_row_col_but_adjacent     22  'TWO NOT TOUCH'   'TRY AGAIN'       MISMATCH
other_wrong                      22  'TRY AGAIN'       'TRY AGAIN'       OK
correct                         121  '(* TWO STARS *)' '(* TWO STARS *)' OK
```

**4 of 5 match.** The mismatch is informative rather than a defect in the netlist: the vector was
*built* to be 2-per-row and 2-per-column with an adjacent pair (four cells of the top-left 2x2 block,
plus a Latin pattern for the rest), but a constructed pattern has no reason to satisfy the hidden
**region** constraint — and the design answers `TRY AGAIN` rather than `TWO NOT TOUCH`. So the design
distinguishes "adjacency is the only violation" from "something else is also wrong", which is
**independent evidence that the region check exists and is consulted before the adjacency message**.

It also means `TWO NOT TOUCH` **cannot be produced without the region map**: constructing a vector
that is 2-per-row, 2-per-col, adjacent *and* 2-per-region requires knowing the regions. That turns the
message stream into a **region-map oracle**: perturb the winning vector (keeping 2-per-row and
2-per-column) and read whether the design still says the region constraint held. That is a
corroboration route for C5 — and, notably, it is the probing method the published solution used, so
in our pipeline it can only ever be the *cross-check*, never the derivation.

## What the winning vector does to C3's blockers

```
flops that move with the winning feed : 87 of 92   (was 58 of 92 under the reference)
flops that never move                 :  i0232  i0275  i0349  i0872  i1531
```

**16 of C3's 21 silent flops now have behaviour**, so C3's unmet "assign all 92 flops" criterion is
now closable with the same dump/classify harness C3 already built — no new machinery.

A second, sharper finding: **~24 flops make exactly 2 changes** under the winning feed (e.g. `i1213`,
`i1250`, `i1339`, `i1454`, `i1553`, `i1584`, several of them high for exactly 22 cycles). Two changes
is what a per-region counter does when its region holds exactly 2 stars — which is what the winning
grid is. That **revives the per-region-counter reading in a checkable form** after C4's re-derivation
had cast doubt on the "13 counters" count: the counters are real, but their enable is not a net that
carries the region one-hot.

## What is still not found: the 121-cell map

`probe_e1b.py` tested the cleanest possible formulation — the map as a set of nets whose cell-sets
are pairwise disjoint, each containing exactly 2 stars, covering all 121 cells (which is what "11
regions of capacity 2" means for this grid):

```
nets with a non-trivial cell-set          : 450
nets whose cell-set has exactly 2 stars   :  25
disjoint cover of all 121 cells           :  none exists
```

So the region is **not** decoded as a one-hot per-position signal — the design does not hold a net
per region that is high on that region's cells. Combined with C4's results (no pure diagonal, no
binary region id that changes only at region boundaries, carve-outs like *column 6 minus rows 3 and
9*), the map must be produced by an arithmetic/comparison form over (row, column) rather than by a
decoder — which is the thing left to pin down.

## Close-out: this step now has a gate, and one claim in it was superseded (2026-09-13)

* **A gate.** `tools/checks/check_stepE1.py` (18 checks) drives the winning vector through the
  netlist with the promoted evaluator (`tools/puzzle/verdict.py`) and re-derives, on every run:
  `success` rising at **cycle 126** and at **only** the offset 4 of 4..8; the message `(* TWO STARS *)`
  read off `O`; and four of the five wrong-input classes. The fifth — `two_per_row_col_but_adjacent` →
  `TWO NOT TOUCH` — is asserted to be the *measured* `TRY AGAIN` and named as blocked on the region
  map, so the gate fails if any other class drifts while keeping the gap visible and specific. It also
  re-validates the evaluator against `example_inputs.vcd` first: the numbers above are now derived
  without `iverilog`, and the instrument's agreement with the chip's own waveform is the premise.
* **The same numbers, from a second instrument.** The offsets table, the message table and the
  "only offset 4 accepts" result came from `iverilog` originally; they now come from the
  simulation-free evaluator, and they agree exactly (`recon/derived/e1_messages.json`).
* **Superseded in part.** The paragraph above reading "*~24 flops make exactly 2 changes* ... that
  revives the per-region-counter reading" does not survive R18: the counters are the eleven **column**
  counters, and the fact that a flop changes twice under the winning feed says how many stars its
  column holds, not that it is a region counter. The measurement stands; the reading is withdrawn.
* **C3's blocker is gone** (item 1 above): the winning-vector dump was done in E1, and C3 closed at
  78 of 92 flops classified with the rest reported as a class — see `docs/steps/C3.md`.
