## 1. What C1 is for

Every check through Phase B compared our artifacts with **evidence about themselves**. B7 broke
that pattern once, on the warm-up, and it was the only time an independent answer existed. The chip
has one too, and C1 uses it: `asic-puzzle-2026/example_inputs.vcd` is a real simulation of the real
design. Its *outputs* are ground truth for our recovered netlist and for our 69 name-derived cell
models.

The README is explicit that the waveform does not contain the winning input, and that is a feature
here rather than a limitation: it exercises the **wrong-input path**, and `success` staying low for
all 312 cycles is a prediction our netlist has to reproduce.

## 2. The timing convention, measured rather than assumed

Read off the file, and asserted by both the stage and the gate:

| fact | value |
|---|---|
| `clk` edges | **625**, every one exactly **5000 ps** apart |
| first rising edge | **5000 ps** |
| every change to `rst_n` / `enable` / `I` | on a **falling** edge |
| cycles | **312** |

So "cycle *k*" is *t* = 5000 + 10000*k* ps: the register state **after** the rising edge at that
instant — which is what a VCD dumps — together with the stimulus held across the cycle. The harness
samples **1 ps after** the rising edge, so a rising edge and an assignment can never race. The gate
re-derives the same table sampling **at** the edge, i.e. at a different instant, and requires the two
to be identical: that pins the convention instead of restating it.

## 3. The stimulus is transcribed, not authored

`emit_testbench` writes the reference's own change list as `#delay` assignments — 95 timed lines
covering every change on `rst_n`, `enable` and `I`. The only thing not transcribed is the clock, and
that is the one property that can be asserted (`always #5000`), which is why §2 exists.

The waveform resolves to exactly what the plan predicted:

```
enable runs                       : [[4, 124], [160, 280]]  (lengths [121, 121])
output streams                    : 125..133 = 'TRY AGAIN', 281..289 = 'TRY AGAIN'
success high in reference         : 0 cycle(s)
```

Two attempts, 121 bits each, **different vectors** (the second begins with `I=1` where the first
begins with `I=0`), each answered nine cycles later with `TRY AGAIN` and then held at `0x00`. The
two feed vectors are recorded in the artifact — they are AC1-adjacent facts and the only complete
inputs we hold besides the puzzle's own.

### "Byte-exact" means semantic equality, and the difference is stated

Two simulators never agree on a VCD byte-for-byte: identifier characters, dump granularity, scope
nesting — this reference emits one `$scope` block *per signal*, which no simulator we know of does —
and x-propagation detail all differ. So the deliverable is stricter where it matters and explicit
about where it cannot be: **every value of every signal at every sampled instant, `x` included**.
A byte diff of two VCD files was never achievable and is not what AC5 is verified to mean.

## 5. The undriven net: resolved, and resolved narrowly

B5 enumerated exactly one net with no driver — cluster 806, terminals `a311o_2.A1` and `a31oi_2.A1`,
both inputs. B7 predicted C1 would "show it as X". Measured, it reads **`z`**: 4-state simulation
gives an undriven `wire` high impedance, while `x` is what an unwritten `reg` reads. The prediction
was right that the value is undefined and wrong about which flavour, and the correction is recorded
rather than glossed (B7's §6 and the plan both said "X" and both now say `z`).

The interesting question is not the value but whether it reaches an output, and that is answered by
runs rather than argument — the same replay with the wire **forced to 0** and **forced to 1**:

| run | cycles | matches the reference | cycles differing from the unforced run |
|---|---|---|---|
| unforced | 312 | yes | — |
| `n806` forced 0 | 312 | yes | **0** |
| `n806` forced 1 | 312 | yes | **0** |

Both extremes leave every interface output identical, over the whole waveform. The claim is
deliberately narrow: **nothing observable at the interface rests on this net under this stimulus.**
"Inconsequential pin" is *not* the claim — the masking depends on the other inputs of its two
consumers, which are state-dependent, so **E1 re-probes it on the winning vector**, where the design
reads its inputs for real. That is a carried-forward item, not a footnote.

## 6. What the replay can actually see — measured, not assumed

2808 comparisons sounds like strength and is not: it is a **count of comparisons**. The reference is
294 idle cycles around 18 cycles of one constant message, so the replay constrains the design's
*timing* tightly and its message *content* weakly, and a netlist wrong in some other way could match
it exactly.

Phase B's review established this the hard way (F1: the or-family was broken and all 18 gates
passed). C1 does the experiment systematically. `model-power` negates each cell model in turn in a
scratch rebuild of `build/cells.v` — the tree is never touched — and re-runs the replay:

```
models negated                    : 66 of 69 (3 physical-only: decap, diode, tapvpwrvgnd)
C1 caught                         : 37
C1 silent (a wrong model would pass): 29
```

| | models |
|---|---|
| **caught** (37) | the negation moves 18–312 output cycles; e.g. `or2_2` **140 cycles from cycle 3**, `a21o_2` 194, `and3_2` all 312, `o211a_2` 48 from cycle 103, `dfrtp_2` 316 |
| **silent** (29) | `a2111oi_2`, `a21bo_2`, `a221o_2`, `a22o_2`, `a22oi_2`, `a311o_2`, `a31oi_2`, `and2_2`, `and3b_2`, `buf_2`, `clkbuf_4`, `conb_1`, `dfstp_2`, `nand2b_2`, `nor4_2`, `o211ai_2`, `o21a_2`, `o21ai_2`, `o21bai_2`, `o221a_2`, `o22ai_2`, `o2bb2a_2`, `o31ai_2`, `o32a_2`, `o32ai_2`, `or3b_2`, `or4_2`, `or4b_2`, `or4bb_2` |
| **not mutable** (3) | `decap_3`, `diode_2`, `tapvpwrvgnd_1` — physical-only, no logic |

Two things follow, and both are stated in the artifact:

1. **F1's break is now machine-checked.** Negating `or2_2` moves 140 output cycles starting at cycle
   3. In the Phase B review the same break passed all 18 gates; C1 is the first oracle in the
   project that sees it.
2. **C1 is partial, by measurement.** For those 29 models a wrong model would pass C1. They are not
   necessarily unused — in fact **all 69 masters are instantiated** in the chip — they are simply
   not *observable at the interface* under this stimulus. This is the reason C2 (warm-up equivalence,
   exhaustive) is not redundant, and it replaces B7's unquantified "the models are still hypotheses"
   with a number.

A third thing falls out as a cross-check: **both consumers of `n806` — `a311o_2` and `a31oi_2` — are
silent**, which is §5's forced-run conclusion reached from the other direction. Two independent
routes, same answer.

## 7. The gate, and the control that keeps it honest

`check_stepC1.py` (83 checks) does not take the artifact's word for anything:

- **regenerates both C1 outputs hermetically** and requires byte equality, then asserts the tree was
  not rewritten;
- **re-reads the waveform itself**, one identifier at a time from the raw text, and derives the whole
  expectation from the *transition list* — counting and ordering changes — rather than by sampling
  the stage's table; it samples at a **different instant** (§2);
- **re-runs the simulation** three times from the committed netlist and compares against its own
  derivation, so "we matched" is never evidence;
- **re-measures four cell-model negations itself** (two the report says are caught, two it says are
  silent) and requires the exact same wrong-cycle counts: `or2_2` 140, `a311o_2` 0, `inv_2` 18,
  `or4_2` 0;
- pins the shape of the evidence rather than letting a big number imply strength: 312 cycles, 18
  message cycles, 294 idle, two identical 9-byte streams, and both feed vectors non-degenerate.

And it carries a **negative control**, because a comparison that silently compares nothing looks
exactly like a correct one: the same harness with the stimulus moved by one clock period must
**fail** this gate's comparison. It does (`moving the stimulus one cycle makes this comparison FAIL`).

## 8. Two bugs this step's own gate caught in my C1 code

1. **The supply ports are `inout`.** The first harness tied `.VGND(1'b0)` and `.VPWR(1'b1)`; iverilog
   refused with *"expression not valid as argument to inout port … must support continuous
   assignment"*. Fixed by declaring `wire VGND/VPWR` and assigning them. The stage had already
   printed every headline number before the compile failed — the same shape as B7's duplicate-wire
   bug: **only the compile check sees it.**
2. **A missed prediction, corrected in two documents.** "C1 will show it as X" is wrong; it reads
   `z`. Recorded in `docs/steps/B7.md` §6 and in the plan, not quietly fixed.
