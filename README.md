# Jane Street ASIC Puzzle (2026) — an independent reconstruction

The 2026 Jane Street puzzle shipped a **GDSII layout** and nothing else: a chip that reads a
121-bit bitmap, and answers with a message. This repository contains our own end-to-end
reconstruction of that chip — from the layout polygons to the emitted netlist to the answer — built to
the protocol in [`AGENTS.md`](AGENTS.md).

**The published answer is known and was deliberately not followed.** The writeup exists and is
recorded (with its two non-reproducing claims) in [`docs/02_known_solution.md`](docs/02_known_solution.md);
what this repo claims is the *method* — recover the netlist from the chip's own standard-cell masters
(no PDK, no LEF), find the hidden constraint by measuring the design, and solve it with our own search.
Every number below is machine-checked by a gate, and the artifacts are regenerable byte-for-byte.

## Status: what is verified, and what is not

| | Criterion | Status |
|---|---|---|
| AC1 | the exact 121-bit input vector | **PASS** — derived by our own search over five constraints, two independently written enumerators agreeing, both bit orders equal to the contract |
| AC2 | `success` asserts at cycle 126 | **PASS** — at feed offset 4 and at no other offset |
| AC3 | output `(* TWO STARS *)` | **PASS** |
| AC4 | the four wrong-input messages | **PASS** — `EMPTY SKY`, `BIG BANG`, `TRY AGAIN`, and `TWO NOT TOUCH` reproduced on 23 constructed boards (and *not* on the 8 controls) |
| AC5 | byte-exact replay of `example_inputs.vcd` | **PASS** — 2808 output bits, 0 mismatches, 0 `x`/`z` |
| AC6 | the hidden region map, spelled "JS" | **PARTIAL** — the partition is recovered from the design's own latches and the chip's message corroborates it; it is **not** confirmed as the unique rule, and the "JS" spelling is **not** reproduced |

AC6 is `PARTIAL` on purpose. See [What we do not claim](#what-we-do-not-claim).

### The upstream input

The puzzle's own repository (the GDS, the reference VCD and the warm-up design) is not redistributed
here. Place it at `asic-puzzle-2026/` in the repository root; it must contain `puzzle.gds`,
`example_inputs.vcd` and `warmup/`. It is never written to: every gate fails if shipped code writes
inside it. If it is missing, the prerequisite check says so and stops before building anything:

```
./.venv/Scripts/python.exe -m tools.puzzle reproduce --check
```

## Quick start

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt

./.venv/Scripts/python.exe -m tools.puzzle reproduce --check    # prerequisites
./.venv/Scripts/python.exe -m tools.puzzle reproduce --plan     # the 30 pipeline stages, in order
./.venv/Scripts/python.exe -m tools.puzzle reproduce --cold     # rebuild everything from scratch
./.venv/Scripts/python.exe tools/checks/run_all.py              # all 33 gates
```

### The full claim: `reproduce --cold`

`--cold` deletes **every derived artifact the repository tracks** (git is the undo — only tracked
files are touched), runs the whole pipeline, rebuilds each one, and compares the rebuilt bytes against
`git show HEAD:<path>`. The run's own report is the one exception, and it says so in its output and in
its artifact: it is written *after* the comparison, so a run that deleted it could never rebuild it
during the pipeline. Expected output, in about **7 minutes**:

```
cold run: removed 32 tracked derived files; git can restore them all
  (recon/derived/reproduction.json is written after this comparison and is therefore not in that set -- see derived_files())
  S0.1   inventory                0.7s  ok   the workspace inventory consumed by B1/B2/B5
  ...
  F6     net806                   6.5s  ok   the one undriven net: geometry, three refutations, the tie
  E3     acceptance               0.1s  ok   assert AC1-AC6 against tools/target.py
acceptance (0.1s):
  ...
criteria: 5 PASS, 1 PARTIAL, 0 FAIL (of 6; plus the yardstick)
30 stages, 420.7s total, acceptance PASS
  32 of 32 regenerated byte-identically
REPRODUCTION: PASS
```

Timings are printed and deliberately **not** stored: a derived artifact must regenerate
byte-identically, and a clock in a file guarantees it will not.

### Stage runtimes (one measured run)

| Phase | Stages | Time |
|---|---|---|
| S0.1 | `inventory`, `vcd-table` | 0.8 s |
| A — the chip describes itself | `layers`, `via-pairs`, `pin-names`, `pin-geom`, `pin-coverage` | 1.9 s |
| B — connectivity and netlist | `instances`, `nets`, `pins-to-nets`, `netlist-check`, `emit`, `cells`, `warmup-regression` | 8.0 s |
| C — what it computes | `vcd-replay`, `model-power`, `warmup-equiv`, `warmup-power`, `decompose`, `rejections`, `region-map` | 251.7 s |
| E1/E2 — the messages | `winning`, `confirm` | 70.8 s |
| F6 — the undriven net | `net806` | 6.5 s |
| D — our own solve | `solve`, `uniqueness`, `load-bearing`, `answer` | 80.9 s |
| E3 — the verdict | `acceptance` | 0.1 s |
| **total** | **30 stages** | **420.7 s measured** (the stage times sum to the same 420.7 s) |

The phases above are grouped for reading, not for running: the pipeline runs `net806` immediately after
`confirm` (it reads E2's artifact) and before the D stages, and `acceptance` closes the plan — E4's gate
asserts that it does.

The waveform and partition stages dominate: `warmup-power` and `region-map` alone are 195.5 s of it.

## How the verification works

* **One gate per executed step.** `tools/checks/run_all.py` discovers them and runs every one; each
  re-derives what it asserts from the artifacts or the netlist rather than trusting a stored number.
* **Fault injection as the meta-gate.** `tools/checks/fault_inject.py` mutates each artifact — claiming
  a second solution, flipping one bit of the answer, upgrading the region map from `PARTIAL` to
  `PASS`, dropping a stage from the reproduction plan — and requires that **the owning gate fails and
  no other gate does**, that no gate rewrites what it judges, and that every artifact is restored.
* **Byte-reproducibility.** Derived artifacts must regenerate identically; `reproduce --cold` is the
  standing test of that claim, and the fault grid includes a mutation that puts a timing into a file.
* **Honesty checks that can fail.** The acceptance matrix is required to keep AC6 at `PARTIAL` and to
  keep its unmet reasons; the plan is required to keep a list of what is *not* claimed.

```bash
./.venv/Scripts/python.exe tools/checks/run_all.py                       # everything
./.venv/Scripts/python.exe tools/checks/fault_inject.py --only "stepD"   # one artifact's mutations
./.venv/Scripts/python.exe tools/checks/check_stepE4.py                  # one gate
```

## What we do not claim

* **Not** that the region map is confirmed. The accepted input is unique, so the chip's verdicts
  cannot distinguish our partition from a look-alike; the chip's *message* corroborates it (23 boards
  agree, 8 controls disagree), and that is the strongest statement the evidence supports.
* **Not** that the printed map spells "JS" — our recovery does not reproduce that reading.
* **Not** that the undriven net changes the answer: cluster 806 is *characterised*, not driven. F6 tests
  and refutes the three ways our extraction could have hidden a driver for it — a constant tie
  (9 966 dbu away), a mis-assigned pin (the engine reproduces both terminals), a cut that could merge
  (zero can) — so the chip is nondeterministic in exactly one place: one character of one of its five
  messages, and neither tie of that net reproduces the published `TWO NOT TOUCH`.
* **Not** that the planned symbolic region-decode differentiator (Δ5) succeeded. It was refuted by
  measurement and replaced; the refutation is recorded rather than dropped.
* **Not** that this was built without AI assistance, or in ignorance of the published solution: both
  are recorded in `docs/01_problem.md` and `docs/02_known_solution.md`.
